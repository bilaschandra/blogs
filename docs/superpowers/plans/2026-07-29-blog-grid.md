# Responsive Card-Grid Blog Listing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the blog listing pages (currently one post per row regardless of viewport width) into a responsive multi-column card grid, and raise the blog listing's pagination cap to 25 posts per page.

**Architecture:** Pure layout fix — widen the shared `SectionBanner` and each listing page's container from `max-w-3xl` to `max-w-6xl`, wrap each page's `PostCard` list in a CSS grid (1/2/3 columns at Tailwind's default breakpoints), and drop `PostCard`'s stacked-list border styling in favor of the grid's own gap spacing. No changes to data, types, or dynamic features.

**Tech Stack:** Next.js 14 (App Router), TypeScript, Tailwind CSS.

## Global Constraints

- Grid breakpoints: 1 column below 640px, 2 columns from 640px (Tailwind `sm:`), 3 columns from 1024px (Tailwind `lg:`) — exact values from the approved spec and mockup.
- Widened container: `max-w-6xl` (1152px), applied to `SectionBanner` and to the home/blog/tags pages' post-list containers.
- **Unchanged, do not touch:** `src/app/about/page.tsx`'s body container (stays `max-w-3xl` for readable prose — only its `SectionBanner` banner widens, since that's shared) and `src/app/blog/[slug]/page.tsx` (the post detail page) in its entirety.
- `PostCard`'s content (image/fallback, tag pills, title, date) is unchanged — only its outer wrapper's className changes (drop the stacked-list border/padding).
- `/blog`'s pagination cap changes from 10 to 25 (`PER_PAGE` constant only — `Pagination.tsx` and `paginate()` need no changes).
- `/tags/[tag]` gets the grid but stays unpaginated — matching its current behavior, not part of this fix's scope.
- No changes to `src/lib/posts.ts`, `src/lib/types.ts`, or any dynamic feature (reactions, comments, CMS).
- No automated test suite for this project (per approved spec) — every task's testable deliverable is manual verification via the dev server (including resizing the browser to confirm breakpoints), not Jest/Vitest.

Replace `src/app/blog/page.tsx` in full:

```tsx
import { getAllPosts, paginate } from "@/lib/posts";
import { PostCard } from "@/components/PostCard";
import { Pagination } from "@/components/Pagination";
import { SectionBanner } from "@/components/SectionBanner";

const PER_PAGE = 25;

export default function BlogPage({
  searchParams,
}: {
  searchParams: { page?: string };
}) {
  const page = Number(searchParams.page ?? "1") || 1;
  const { items, currentPage, totalPages } = paginate(getAllPosts(), page, PER_PAGE);

  return (
    <main>
      <SectionBanner title="All Posts" />
      <div className="mx-auto max-w-6xl px-4 py-8">
        <div className="grid grid-cols-1 gap-x-8 gap-y-10 sm:grid-cols-2 lg:grid-cols-3">
          {items.map((post) => (
            <PostCard key={post.slug} post={post} />
          ))}
        </div>
        <Pagination currentPage={currentPage} totalPages={totalPages} basePath="/blog" />
      </div>
    </main>
  );
}
```
